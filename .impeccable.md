## Design Context

### Users

Developers who use multiple AI coding agents and subscriptions, often from a
terminal. They want to continue a task when an account reaches a limit or another
agent is a better fit, while preserving context and controlling disclosure.

### Brand Personality

Playful, capable, polished. The README should explain the idea visually and feel
memorable. The user rejected the first restrained graphite, paper, and forest
proposals as boring, and requested brighter themes, funny illustrations, and
recognizable Claude, Codex, and Kimi marks in handover diagrams.

### Aesthetic Direction

Use the makeover palette library and live design library as starting points.
Show complete designs on localhost before asking the user to choose. The user selected Night Shift / Distinction from the 12-style second round.
The final header adds expressive relay characters in the selected palette, combining
the humor of the cartoon and clay references. Use the noir canvas, colorful hex texture, wide display typography, and explicit
Claude/Codex/Kimi handover diagram as the established direction. Future open-ended
style exploration should offer a browsable gallery of 25+ complete visual previews.

### Design Principles

1. Show the same work moving between different agents through a clear visual
   metaphor, such as a folder passed between characters.
2. Use expressive color and illustration with carefully composed type; keep
   prose concise and readable.
3. Build complete visual candidates with real content. Palette descriptions
   alone do not help this user decide.
4. Keep the public README focused on AgentSwapper. Do not name or compare
   competing switching products.
5. State the development status honestly. Do not invent installation commands,
   released features, integrations, usage numbers, or endorsements.
6. Use local, self-contained assets and preserve light/dark readability and
   mobile proportions. Export PNG fallbacks for GitHub rendering.
